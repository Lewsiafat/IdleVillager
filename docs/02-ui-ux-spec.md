# 02 — UI / UX 規格

## 設計原則

**第一眼看數量，第二眼看誰，第三步點擊跳回。** 不做遊戲式 Dashboard；用輕巧的「AI 小村民」動畫強化辨識。

## 1. 選單列（永遠可見）

預設文字示意：`⚒ 3  ✋ 2  💤 1`

- `⚒`：工作中
- `✋`：等待核准或需要使用者操作
- `💤`：閒置
- 完成未查看可選擇增加 `✓ n`；顯示規則需一致。
- 值為 0 的類別預設隱藏；必要時可在設定開啟固定欄位。
- 不依賴顏色辨識：圖示與數字必須共存。
- 狀態列文字長度應適合 macOS Menu Bar，避免超長名稱。
- 多數 Agent 時保持總數模式；少數 Agent 才可選角色模式。
- 少量角色模式：Session 數量**低於**門檻（預設門檻 4，也就是最多 3 個 Session）且已連線時，選單列改為每個 Session 一個靜態角色加狀態圖示；達到或超過門檻、沒有 Session 或斷線時自動回到數量模式。
- 低干擾提醒：待核准數量增加時，選單列短暫強調約 3 秒後恢復，不閃爍、不使用音效或系統通知。**預設開啟**，可在設定關閉。

## 2. 展開清單（Popover）

概念示意：

```text
IdleVillager            6 Agents

● Backend Project
  ▾ API 開發 · Tab 1
    ✋ Claude Code · Pane 2   等核准
    ⚒ Codex · Pane 1         幹活中
  ▾ 測試 · Tab 2
    💤 Codex · Pane 1         閒置

● Frontend Project
  ▾ UI 開發 · Tab 1
    ⚒ Claude Code · Pane 1   幹活中

[點選一列 → 定位 Herdr 對應 Pane]
```

- 預設將需操作的項目排在易發現處，但要保留其 Workspace / Tab / Pane 脈絡。
- 每列：角色、Agent 名稱、Pane 識別、狀態；可附上極短的等待原因。
- 點擊列即定位；不需要額外確認對話框。
- 使用者可收合 Tab 群組，避免清單過長。
- 若 API 無法準確定位則應給出明確失敗提示，不可假裝成功。
- 底部來源文字來自 Adapter 的來源描述。尚未驗證 Herdr API 時不得顯示「Herdr · 已連線」；示範資料顯示「來源：示範資料 · 已連線」。
- 示範模式的聚焦顯示「示範模式無法切回」，Popover 保持開啟，不可假裝已經切回。
- Tab 收合時，Tab 標題旁顯示該 Tab 內最高優先度狀態的圖示與 Session 數量（例如 `✋ 2`），收合後仍看得出裡面有沒有急件。
- 資料過期（久未更新、斷線或重連中）的列，在狀態短文字後加上「（過期）」，例如「幹活中（過期）」，不只靠顏色或透明度表達。
- Popover 底部資訊區提供「結束 IdleVillager」按鈕。App 只出現在選單列、沒有 Dock 圖示與應用程式選單，這是使用者結束 App 的入口。

### 2.1 半透明背景（可在設定切換）

- 設定視窗的「外觀」區段提供「清單使用半透明背景」開關，**預設關閉**，維持原本的不透明外觀。選擇會保存在 macOS 使用者偏好（`UserDefaults`），重開 App 後保留。
- 開啟後 Popover 的背景改為半透明材質，透出模糊的桌面與後方視窗。切換後立即生效，Popover 開著時也會當場重繪，不需要重開 App。
- 實作採用 AppKit 的 `NSVisualEffectView`（材質 `hudWindow`、混合模式 `behindWindow`、狀態固定為 `active`）。`behindWindow` 的意思是材質取樣的是視窗**後方**的畫面，因此桌面才透得出來。不採用 SwiftUI 的 `.ultraThinMaterial` 等材質，原因是它們放在 `.background` 時只會模糊同一個視窗裡已經畫好的內容，也就是 Popover 自己的背景，桌面透不出來；SwiftUI 對應的 `.containerBackground(_:for: .window)` 需要 macOS 15，而本專案支援 macOS 14。狀態固定為 `active`，是為了避免 Popover 不是焦點視窗時材質變成平板的灰色。
- 系統「輔助使用 → 顯示器 → 降低透明度」開啟時，一律回到不透明外觀，即使使用者開了半透明背景也一樣；此時設定視窗的說明文字改為提示「系統已開啟降低透明度，清單目前維持不透明」。macOS 開啟「增加對比」時也會自動開啟降低透明度，因此高對比需求同樣會得到不透明背景。這個判斷寫在 Core 的 `PopoverBackgroundStyle.resolve`，有單元測試。
- 可讀性：每個 Workspace 圓角區塊在半透明背景時，底下多墊一層 50% 不透明度的視窗背景色，再疊上原本的淡色底，讓列文字、角色與狀態膠囊不會直接壓在雜亂的桌面上。文字與圖示沿用系統的主要與次要前景色，會隨淺色與深色模式自動調整；狀態仍同時以圖示與文字表達，不只靠顏色。
- 目前只有開關，沒有透明度滑桿。日後若要加入滑桿，透明度會作為 `PopoverBackgroundStyle.resolve` 的另一個輸入，畫面仍只讀取判斷結果。
- 待實機確認：淺色與深色模式在不同桌布上的可讀性、Popover 圓角處是否有方形的半透明邊緣，以及 `hudWindow` 與系統預設 Popover 背景的透明度差異是否夠明顯。

## 3. 動畫運用

- Menu Bar 預設以穩定數量為主，不讓整列持續大幅晃動。
- Popover 內才播放具辨識度的輕動畫。
- 等待核准比普通完成更醒目，但不用高頻閃爍。
- 減少動態效果啟用時改用靜態姿勢。

## 4. 視覺尺寸建議（待實機調整）

- Menu Bar 圖示：16–18 pt 視覺尺寸。
- Popover 角色：24–36 pt。
- Popover 寬度：320–420 pt；依語系與螢幕調整。
- 每列可點擊區高度：至少 32 pt，建議 36–44 pt。
- 支援系統明暗模式與高對比需求；半透明背景在系統開啟「降低透明度」時自動改回不透明（見 2.1）。

## 5. 排序優先度

需要使用者操作 > 發生錯誤 > 已完成未查看 > 工作中 > 閒置 > 未知（未知須額外標示，不可隱藏）。


## 6. 介面語言

- 支援繁體中文與英文，本文件的範例文字都是繁體中文介面的用字；英文介面的對應用字見 `Sources/IdleVillagerCore/Resources/en.lproj/Localizable.strings`。
- 介面語言由設定視窗「外觀」區段的「語言」選項決定，預設是英文，不跟隨 macOS 的偏好語言。選項名稱固定用該語言本身書寫（English、繁體中文），不隨目前的介面語言翻譯，讓看不懂目前語言的人也找得到自己的語言。
- 切換後選單列、Popover 與設定視窗立即換成新語言，重開 App 後保留。簡體中文目前不支援。
- 已知限制：
  - 示範模式（`IDLEVILLAGER_DEMO=1`）的示範 Tab 名稱、等待原因與來源名稱「示範資料」在 App 啟動時就建立好，切換語言後要重開 App 才會換。連 Herdr 時沒有這個問題，因為這些文字來自 Herdr。
  - macOS 系統畫的文字（例如設定視窗的標題列）依系統語言顯示，不受這個選項影響，所以可能和介面語言不同。
- 不翻譯的文字：產品名稱 `IdleVillager`、Agent 名稱（Claude Code、Codex、Gemini CLI）、Herdr、來源提供的 Workspace／Tab／Pane 名稱與等待原因，以及衝突描述裡的正規化狀態英文名稱（例如「訊號衝突：Working、Idle」）。
- 英文介面的數量文字會區分單複數，例如 `1 Agent`、`2 Agents`、`1 minute ago`。

## 品牌顯示要求

- Popover 標題固定為 **IdleVillager**；Herdr 只出現在來源/連線資訊。
- 選單列不強制顯示產品全名，以免佔用空間；以村民符號加狀態數量為主。
- 角色造型與狀態互動詳見 `07-brand-identity.md`。
