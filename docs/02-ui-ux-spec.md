# 02 — UI / UX 規格

## 設計原則

**第一眼看數量，第二眼看誰，第三步點擊跳回。** 不做遊戲式 Dashboard；用輕巧的「AI 小村民」動畫強化辨識。

## 1. 選單列（永遠可見）

預設文字示意：`⚒ 3  ✋ 2  💤 1`

- `⚒`：工作中
- `✋`：等待核准或需要使用者操作
- `💤`：閒置
- 完成未查看可選擇增加 `✓ n`；顯示規則需一致。
- 值為 0 的類別預設隱藏；必要時可在設定開啟固定欄位。
- 不依賴顏色辨識：圖示與數字必須共存。
- 狀態列文字長度應適合 macOS Menu Bar，避免超長名稱。
- 多數 Agent 時保持總數模式；少數 Agent 才可選角色模式。

## 2. 展開清單（Popover）

概念示意：

```text
IdleVillager            6 Agents

● Backend Project
  ▾ API 開發 · Tab 1
    ✋ Claude Code · Pane 2   等核准
    ⚒ Codex · Pane 1         幹活中
  ▾ 測試 · Tab 2
    💤 Codex · Pane 1         閒置

● Frontend Project
  ▾ UI 開發 · Tab 1
    ⚒ Claude Code · Pane 1   幹活中

[點選一列 → 定位 Herdr 對應 Pane]
```

- 預設將需操作的項目排在易發現處，但要保留其 Workspace / Tab / Pane 脈絡。
- 每列：角色、Agent 名稱、Pane 識別、狀態；可附上極短的等待原因。
- 點擊列即定位；不需要額外確認對話框。
- 使用者可收合 Tab 群組，避免清單過長。
- 若 API 無法準確定位則應給出明確失敗提示，不可假裝成功。

## 3. 動畫運用

- Menu Bar 預設以穩定數量為主，不讓整列持續大幅晃動。
- Popover 內才播放具辨識度的輕動畫。
- 等待核准比普通完成更醒目，但不用高頻閃爍。
- 減少動態效果啟用時改用靜態姿勢。

## 4. 視覺尺寸建議（待實機調整）

- Menu Bar 圖示：16–18 pt 視覺尺寸。
- Popover 角色：24–36 pt。
- Popover 寬度：320–420 pt；依語系與螢幕調整。
- 每列可點擊區高度：至少 32 pt，建議 36–44 pt。
- 支援系統明暗模式與高對比需求。

## 5. 排序優先度

需要使用者操作 > 發生錯誤 > 已完成未查看 > 工作中 > 閒置 > 未知（未知須額外標示，不可隱藏）。


## 品牌顯示要求

- Popover 標題固定為 **IdleVillager**；Herdr 只出現在來源/連線資訊。
- 選單列不強制顯示產品全名，以免佔用空間；以村民符號加狀態數量為主。
- 角色造型與狀態互動詳見 `07-brand-identity.md`。
