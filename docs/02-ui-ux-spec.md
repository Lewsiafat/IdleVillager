# 02 — UI / UX 規格

## 設計原則

**第一眼看數量，第二眼看誰，第三步點擊跳回。** 不做遊戲式 Dashboard；用輕巧的「AI 小村民」動畫強化辨識。

## 1. 選單列（永遠可見）

預設文字示意：`⚒ 3  ✋ 2  💤 1`

- `⚒`：工作中
- `✋`：等待核准或需要使用者操作
- `💤`：閒置
- 完成未查看可選擇增加 `✓ n`；顯示規則需一致。
- 值為 0 的類別預設隱藏；必要時可在設定開啟固定欄位。
- 不依賴顏色辨識：圖示與數字必須共存。
- 狀態列文字長度應適合 macOS Menu Bar，避免超長名稱。
- 多數 Agent 時保持總數模式；少數 Agent 才可選角色模式。
- 少量角色模式：Session 數量**低於**門檻（預設門檻 4，也就是最多 3 個 Session）且已連線時，選單列改為每個 Session 一個靜態角色加狀態圖示；達到或超過門檻、沒有 Session 或斷線時自動回到數量模式。
- 低干擾提醒：待核准數量增加時，選單列短暫強調約 3 秒後恢復，不閃爍、不使用音效或系統通知。**預設開啟**，可在設定關閉。

## 2. 展開清單（Popover）

概念示意：

```text
IdleVillager            6 Agents

● Backend Project
  ▾ API 開發 · Tab 1
    ✋ Claude Code · Pane 2   等核准
    ⚒ Codex · Pane 1         幹活中
  ▾ 測試 · Tab 2
    💤 Codex · Pane 1         閒置

● Frontend Project
  ▾ UI 開發 · Tab 1
    ⚒ Claude Code · Pane 1   幹活中

[點選一列 → 定位 Herdr 對應 Pane]
```

- 預設將需操作的項目排在易發現處，但要保留其 Workspace / Tab / Pane 脈絡。
- 每列：角色、Agent 名稱、Pane 識別、狀態；可附上極短的等待原因。
- 點擊列即定位；不需要額外確認對話框。
- 使用者可收合 Tab 群組，避免清單過長。
- 若 API 無法準確定位則應給出明確失敗提示，不可假裝成功。
- 底部來源文字來自 Adapter 的來源描述。尚未驗證 Herdr API 時不得顯示「Herdr · 已連線」；示範資料顯示「來源：示範資料 · 已連線」。
- 示範模式的聚焦顯示「示範模式無法切回」，Popover 保持開啟，不可假裝已經切回。
- Tab 收合時，Tab 標題旁顯示該 Tab 內最高優先度狀態的圖示與 Session 數量（例如 `✋ 2`），收合後仍看得出裡面有沒有急件。
- 資料過期（久未更新、斷線或重連中）的列，在狀態短文字後加上「（過期）」，例如「幹活中（過期）」，不只靠顏色或透明度表達。
- Popover 底部資訊區提供「結束 IdleVillager」按鈕。App 只出現在選單列、沒有 Dock 圖示與應用程式選單，這是使用者結束 App 的入口。

## 3. 動畫運用

- Menu Bar 預設以穩定數量為主，不讓整列持續大幅晃動。
- Popover 內才播放具辨識度的輕動畫。
- 等待核准比普通完成更醒目，但不用高頻閃爍。
- 減少動態效果啟用時改用靜態姿勢。

## 4. 視覺尺寸建議（待實機調整）

- Menu Bar 圖示：16–18 pt 視覺尺寸。
- Popover 角色：24–36 pt。
- Popover 寬度：320–420 pt；依語系與螢幕調整。
- 每列可點擊區高度：至少 32 pt，建議 36–44 pt。
- 支援系統明暗模式與高對比需求。

## 5. 排序優先度

需要使用者操作 > 發生錯誤 > 已完成未查看 > 工作中 > 閒置 > 未知（未知須額外標示，不可隱藏）。


## 品牌顯示要求

- Popover 標題固定為 **IdleVillager**；Herdr 只出現在來源/連線資訊。
- 選單列不強制顯示產品全名，以免佔用空間；以村民符號加狀態數量為主。
- 角色造型與狀態互動詳見 `07-brand-identity.md`。
